# M4-05: CI on Linux and on `windows-latest`

**Branch:** `m4-05-ci`, from `main` after M4-03 and M4-04 have merged. **Wave 3**, beside M4-06. **Agent:**
`sc-builder`, then `sc-reviewer` and `sc-inspector`.

**This order pushes.** Its checks run on GitHub Actions, so its brief must allow `git push origin m4-05-ci`
(CLAUDE.md: nobody pushes unless the brief says so). Pushing a workflow file from a session works [here, planning
job].

## Intent

Nothing of v0.1 can be tried on Windows hardware until M4-08, so CI is where Windows problems show first: PowerShell
5.1, the cpu lane's wheels, Node and npm on Windows, torchaudio with torch 2.15 in allin1's environment, the path
check, the whole pipeline on a real Windows box, and the UI's guards.

The Linux job keeps `main` honest: the locks, the suite with scan-chart and allin1, and the same synthetic clip end
to end. It never uses copyrighted audio: the clip is generated by code in the run (DESIGN 4.6).

## Scope

Creates:
- `.github/workflows/ci.yml`;
- `packaging/ci/make_clip.py`: the generator from the planning job, unchanged except a module docstring that says
  what it is;
- `packaging/ci/check_gate.py`, `packaging/ci/check_no_audio.py`, `packaging/ci/ui_guards.py`;
- `packaging/ci/run-hooks.sh`, `packaging/ci/run-hooks.ps1`;
- empty `packaging/ci/linux.d/` and `packaging/ci/windows.d/`, each with a `README.txt` naming the hook contract.

Must not touch:
- `songcharter/`, `tests/`, `pyproject.toml`, the locks, and `packaging/windows/` (if a Windows bug shows, report it:
  the director sends the fix to the owning order's branch or a fix order);
- `docs/`.

## Spec

### `ci.yml`

- **Triggers:** `push` to `main` and `m4-*`, `pull_request`, `workflow_dispatch`. `permissions: contents: read`.
  `concurrency: ci-${{ github.ref }}`, cancelling the older run.
- **Actions:** `actions/checkout@v4`, `actions/cache@v4`, `actions/setup-node@v4`, `actions/upload-artifact@v4`.
- **Shared environment:** `SC_ROOT=${{ runner.temp }}/sc` and `SONGCHARTER_HOME=$SC_ROOT`. Every step that must
  not reach the network sets `HTTPS_PROXY` and `HTTP_PROXY` to `http://127.0.0.1:9`, a dead proxy.
- **Caches** (keys hash the files that pin their content):
  - the uv cache, by `uv.lock` and `packaging/allin1/uv.lock`;
  - `$SC_ROOT/models` and `$SC_ROOT/runtime/autochart/models`, by `songcharter/separate.py`,
    `songcharter/engines/sections.py`, `songcharter/engines/adtof.py` and `packaging/autochart/engine-files.sha256`.

#### Job `linux` (`ubuntu-latest`, `timeout-minutes: 90`)

1. `python3 -m pip install uv==0.13.5`. Node 24.19.0 through `setup-node`.
2. `uv lock --check`, then `uv lock --check --project packaging/allin1`.
3. `uv run --no-project python packaging/check_wheels.py` must exit 0.
4. `uv sync --frozen --extra cpu --extra app --extra dev`.
   `UV_PROJECT_ENVIRONMENT=$SC_ROOT/runtime/allin1 uv sync --frozen --project packaging/allin1 --extra cpu`.
5. `(cd tools/scan-chart && npm ci)`. Then the suite exactly as CLAUDE.md runs it, with
   `SONGCHARTER_ALLIN1_PYTHON=$SC_ROOT/runtime/allin1/bin/python`. Expected: 0 failures, and no skip for the allin1
   probe or the scan-chart tests.
6. `.venv/bin/python -m songcharter.runtime setup --root $SC_ROOT --app $PWD --lane cpu --lane-reason ci` exits 0
   or 1 (doctor's problems are printed; on Linux none are expected).
7. `.venv/bin/python packaging/ci/make_clip.py $RUNNER_TEMP/clip.wav 30`. Then `.venv/bin/python -m songcharter.launch
   chart $RUNNER_TEMP/clip.wav --out $RUNNER_TEMP/out/Clip --device cpu --threads 4` exits 0, and
   `packaging/ci/check_gate.py $RUNNER_TEMP/out/Clip` exits 0.
8. **Offline:** the same chart with `--out $RUNNER_TEMP/out2/Clip` and the dead proxy exits 0, and `check_gate.py`
   passes. `launch` has set `HF_HUB_OFFLINE` and `SONGCHARTER_OFFLINE`; the dead proxy makes any request that
   slips through fail.
9. **Guards:** `.venv/bin/python packaging/ci/ui_guards.py --launcher ".venv/bin/python -m songcharter.launch"`
   exits 0.
10. `bash packaging/ci/run-hooks.sh linux`.
11. **Artifacts** (`if: always()`):
    - `out/Clip/report.json`;
    - the work folder's `pipeline.json` and `preview/overview.png`;
    - `$SC_ROOT/doctor.json`, `$SC_ROOT/runtime/runtime.json`, `$SC_ROOT/logs/`;

    after `check_no_audio.py` on the upload folder.

#### Job `windows` (`windows-latest`, `timeout-minutes: 150`, `defaults.run.shell: powershell`, that is 5.1)

1. **Stage the app the way the installer will:**
   - copy `packaging\windows\bootstrap.ps1` and `songcharter.cmd` to the checkout's root;
   - write `VERSION` (`ci-<short sha>`);
   - `python -m pip install uv==0.13.5`, then copy `uv.exe` from `python -m pip show -f uv`'s location to
     `bin\uv.exe`.
2. `packaging\windows\Test-Bootstrap.ps1` exits 0.
3. **The real first launch:** `.\bootstrap.ps1 -Root $env:SC_ROOT -App $PWD -Lane auto`.
   - The exit code is 0 or 1.
   - `runtime.json`'s lane is `cpu`, and its reason contains "no NVIDIA GPU".
   - Time it, and print the time.
4. **Every lane installs on Windows:** for each of `cpu`, `cu126`, `cu132`: `bin\uv.exe sync --project . --frozen
   --dry-run --no-dev --no-editable --managed-python --python 3.13.17 --extra app --extra <lane>`, with
   `UV_PROJECT_ENVIRONMENT` in a temporary folder. Exit 0.
5. **Doctor:** `cmd /c songcharter.cmd doctor --json $env:RUNNER_TEMP\doctor.json` exits 0. A PowerShell check of
   the JSON:
   - `device.chosen` is `cpu`, and `guitar_device` is `cpu`;
   - `paths.ok` is true and `paths.node_long_path_ok` is true;
   - `components.allin1.ok` is true (this is the torchaudio 2.11.1 check);
   - `components.scan_chart.ok` and `components.autochart.ok` are true.
6. **The clip, through the launcher:**
   - make the clip with `$env:SC_ROOT\runtime\env\Scripts\python.exe packaging\ci\make_clip.py`;
   - `cmd /c songcharter.cmd chart $env:RUNNER_TEMP\clip.wav --out $env:RUNNER_TEMP\out\Clip --device cpu` exits 0;
   - `check_gate.py` passes;
   - print the stage times from `pipeline.json`.
7. **Offline** re-run, as on Linux.
8. **The bootstrap again:** exits 0 or 1 in under 5 minutes. Its log says every step was verified, and no download
   happened.
9. **Guards:** `ui_guards.py --launcher "cmd /c songcharter.cmd"`.
10. `packaging\ci\run-hooks.ps1 windows`.
11. **Artifacts** as on Linux, plus the bootstrap log.

### `packaging/ci/check_gate.py <song folder>`

Exit 0 only when every check holds; otherwise list what failed, one line each.
- `report.json`'s `gate.ok` is true;
- `gate.scan_chart.ran` is true, `playable` true, and `chart_issues` 0;
- the folder holds `notes.chart`, `song.ini`, `song.ogg` and `report.json`;
- `tracks` has guitar, bass and drums, each with Expert onsets above 0. The planning run had 23 / 120 / 119; a part
  can be thin, but not absent.

### `packaging/ci/check_no_audio.py <folder>`

Exit 1 if any file there has an audio extension (`.wav .mp3 .ogg .flac .m4a .opus .aac .wma .aif .aiff`) or starts
with `RIFF`, `OggS`, `ID3`, `fLaC` or an MPEG frame sync.

### `packaging/ci/ui_guards.py --launcher CMD`

1. Start `CMD ui --no-browser --port 8799` with `SONGCHARTER_HOME` set. Wait up to 60 s for `/api/hello`.
2. Assert:
   - `Host: evil.example` gives 403;
   - a POST without `X-Songcharter` gives 403;
   - one with `Origin: http://evil.example` gives 403;
   - a `.txt` upload gives 415.
3. Upload the clip and start a job. When the `separate` stage starts (from the SSE stream), cancel.
4. Within 30 s, assert:
   - the job reads `cancelled`;
   - no process whose command line holds `songcharter.cli chart`, `ac_headless.cjs` or `allin1_runner.py` is left.
     On Windows, read each process's `CommandLine` from `Get-CimInstance Win32_Process` through `powershell
     -NoProfile -Command`; elsewhere, `ps -eo pid,args`;
   - no `.partial` folder is left in the library.
5. Stop the server.

### Hooks

- `run-hooks.sh linux` runs each `packaging/ci/linux.d/*.sh` in name order with `bash -euo pipefail`.
- `run-hooks.ps1 windows` runs each `packaging/ci/windows.d/*.ps1` with `powershell -NoProfile -ExecutionPolicy
  Bypass -File`.
- Hooks see `SC_ROOT`, `SONGCHARTER_HOME`, `SC_CLIP` (the clip) and `SC_SONG` (its song folder). Any non-zero exit
  fails the job.
- Later orders add hooks; nobody else edits `ci.yml` in v0.1.

   The report gives:
   - the run's URL;
   - each job's time;

   Reading Actions results from a session may be blocked by the proxy (`actions/permissions` was refused in the
