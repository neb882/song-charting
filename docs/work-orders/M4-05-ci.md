# M4-05: CI end to end, in Ubuntu 26.04

**Branch:** `m4-05-ci`, from `main` after M4-03 and M4-04 have merged. **Wave 3**, beside M4-06. **Agent:**
`sc-builder`, then `sc-reviewer` and `sc-inspector`. **This order pushes** its branch to run CI.

## Intent

Before anything reaches the friend, CI does what he will do, on the same Ubuntu, from nothing:
- install from the release assets as a plain user;
- run `doctor`;
- chart a song;
- use the page;
- cancel a run;
- chart offline;
- uninstall and reinstall.

There is no GPU on the runner, so this is the cpu lane. CUDA is M4-08's. It never uses copyrighted audio: the clip
is made by code (DESIGN 4.6).

## Scope

Creates:
- `packaging/ci/linux.d/50-e2e.sh`;
- `packaging/ci/e2e.sh` (runs inside the container);
- `packaging/ci/ui_guards.py`;
- `packaging/ci/fake-nvidia-smi`.

Must not touch: `songcharter/`, `tests/`, `ci.yml` (M4-05a's), and the other orders' hooks. Report a bug the run
finds to the director, for the owning order or a fix order.

## Spec

### Hook `50-e2e.sh` (on `ubuntu-latest`)

1. `bash packaging/release/build.sh 0.1.0-ci-<sha> $CI_TMP/dist`.
2. `docker run --name sc-e2e -v $CI_TMP/dist:/dist:ro -v $PWD/packaging/ci:/ci:ro ubuntu:26.04` runs
   `/ci/e2e.sh`:
   - first as root: `apt-get update && apt-get install -y curl ca-certificates git xz-utils` (the WSL image's tools
     [doc: its manifest]) and `useradd -m friend`;
   - then the rest as `friend`, with `HOME=/home/friend` and a song folder named `Jörg's Söngs`, so non-ASCII names
     and spaces are tried.
3. Copy `doctor.json`, `runtime.json`, the logs, the clip's `report.json`, `pipeline.json` and the preview overview to
   `$CI_ART/e2e/`, after `check_no_audio.py`.

### `e2e.sh` (in the container, as `friend`), each check printed and timed

1. **The install, interrupted.** Start `bash /dist/install.sh --from /dist --lane auto --yes`, kill it when its log
   shows the uv sync, then run it again.
   - The second run exits 0.
   - `runtime.json`'s lane is `cpu`, and the reason contains "no NVIDIA GPU found".
   - Record the install's time and `du -sh` of `~/.local/share/songcharter`, `~/.cache/uv` and
     `~/.cache/songcharter`. These are the cpu lane's real figures for the guide and the uninstall question.
2. **Doctor:** `songcharter doctor --json /tmp/d.json` exits 0, with `wsl` null, `guitar_device` cpu, and
   `components.allin1.ok` true (the allin1 environment on Ubuntu 26.04).
3. **Doctor with a GPU on PATH:** the same with `/ci/fake-nvidia-smi` first on PATH, as `nvidia-smi` (prints `NVIDIA
   GeForce RTX 4070, 581.57, 12282, 8.9`).
   - `gpu.name` is `NVIDIA GeForce RTX 4070`;
   - `device.reason` is "this install's torch has no CUDA (the cpu lane)".
4. **The clip:** `make_clip.py` (from `/ci`, run by the installed Python), then `songcharter chart "<clip>" --out
   "<song folder>/Clip" --device cpu`.
   - Exit 0, and `check_gate.py` passes.
   - Print the stage times from `pipeline.json`.
5. **The page:** `python /ci/ui_guards.py --cmd "songcharter ui --no-browser --port 8799"` (below) exits 0.
6. **Offline:** `docker network disconnect bridge sc-e2e` (from the hook, between steps). Then chart the clip into a
   new folder.
   - Exit 0, and `check_gate.py` passes.
   - Reconnect afterwards.
7. **Uninstall, keeping the downloads:** `songcharter uninstall`, answering **No** (`printf 'n\n' |`). Then the
   install again:
   - exit 0;
   - no download: the log has no `fetch` progress lines, and uv reports none;
   - under 3 minutes.
8. **Uninstall, deleting everything:** with **Yes**. Then `~/.local/share/songcharter`, `~/.cache/songcharter` and
   `~/.local/bin/songcharter` are gone.

### `ui_guards.py --cmd CMD`

1. Start CMD and wait up to 60 s for `/api/hello`.
2. Assert:
   - `Host: evil.example` gives 403;
   - a POST without `X-Songcharter` gives 403;
   - `Origin: http://evil.example` gives 403;
   - a `.txt` upload gives 415.
3. Upload the clip and start a job with the defaults.
4. Follow the SSE stream. **At the first `take` event**, post the cancel. That is when autochart's `node` is running.
   Separation runs in the server's child Python, so cancelling then would not prove that Node goes too (the
   advisor's finding 4).
5. Within 30 s, assert:
   - the job reads `cancelled`;
   - `ps -eo pid,args` shows no `node`, `ac_headless.cjs`, `autochart-engine.cjs`, `allin1_runner.py` or
     `songcharter.cli chart`;
   - no `.partial` folder is left in the library.
6. Start the same job again: it finishes `done` with `ok: true`, and the stages before the guitar are cached (the
   cancel kept them).
7. Stop the server with SIGTERM: it exits within 5 s.

## Done means

1. [dev] `bash -n packaging/ci/e2e.sh packaging/ci/linux.d/50-e2e.sh` and `python -m py_compile
   packaging/ci/ui_guards.py` pass. `ui_guards.py` against a local `songcharter ui` (with M4-03's install in the
   container, as a plain user) exits 0.
2. [CI] After the push, `ci` is green on `m4-05-ci`, both jobs and every hook. Report:
   - the run's URL;
   - the install's time and its disk figures (step 1);
   - the clip's stage times;
   - the offline and reinstall times.

   If the session cannot read the Actions API, the owner reads the run, and the report says so.
3. Whatever fails is reported with the step and its last lines, not worked around in this order's files.
