# M4-10: lyrics — the friend pastes the lyrics, songcharter times every word

**Branch:** `m4-10-lyrics`, from `main` during wave 2, beside M4-03 and M4-04. **Agent:** `sc-builder`, then
`sc-reviewer`. May push its branch to run CI. Committed on 2026-11-04 from the brief it was built from, so the
lyrics rule's exception below lives in the repository.

## The lyrics rule (absolute)

The owner's standing rule is: never look up, quote or reproduce song lyrics. It binds every agent and every file in
the repository, absolutely. The owner has allowed exactly one use of the human charts' lyrics, timing only:

- Scripts may read the reference charts' lyric events internally, to feed the words to an aligner and compare
  timings.
- Nothing may print, log, save, commit or return any word text. That covers reports, test fixtures, commit
  messages, your replies, error messages and debug output.
- Report only indices and timings: "word 37: +52 ms". Never "word 'x'".
- Do not open chart files' [Events] or vocal tracks with Read, cat, grep or anything else that would show them to
  you. Write scripts that read them and print only numbers.
- If an error message could contain a word (a tokenizer error, say), catch it and print its type only.
- Tests and fixtures use made-up words only ("zorp blen") and audio generated by code. Never real lyrics.
- Never transcribe lyrics from audio, not even to test. The feature aligns text the user provides; it never
  generates lyrics. Transcribing on the user's own machine is out of scope too: an idea for the owner, not a plan.

**The app's rule.** songcharter may keep the text a user pasted in its own state folder (`<home>/state/`) until that
song is charted, then deletes it. The text is never in the diagnostics zip, a log or a report: only the chart holds
the words.

## Why

The owner's friend, who plays Guitar on Expert, wants on-screen lyrics in Clone Hero. He pastes the lyrics; the
app does the timing.

Clone Hero reads lyrics as events in the chart's [Events] section:
- `phrase_start`;
- `lyric <syllable>`, with `-` joining syllables and other Clone Hero / Rock Band conventions; check scan-chart's
  parser and Clone Hero's documentation for the exact rules;
- `phrase_end`.

## Phase A: choose the aligner by measurement (report before building on it)

1. **Find which reference songs have human-timed lyrics** (`$EVAL_DATA/refs/<id>/ref`, six songs). Report counts
   only: lyric events and phrases per song. Use the importers or scan-chart's parser in a script.
2. **Candidates:** at least three forced aligners that work from a given text and audio and run on Linux in our
   lanes (torch 2.15 cpu/cu132, 2.14.1 cu126; Python 3.13). For example:
   - torchaudio's MMS_FA pipeline, if torchaudio 2.11 still ships it;
   - the `ctc-forced-aligner` package;
   - WhisperX-style wav2vec2 alignment;
   - an aligner of your choice.
   For each, record its licence, its weights' licence (non-commercial is acceptable: the tool is free), its install
   size and dependencies, and whether it needs a compiler or system packages.
3. **Evaluate on the seeded vocal stems** in the separation cache, the same stems the pipeline uses.
   - Feed each reference song's lyric words (internally) to each aligner.
   - Compare each word's aligned start with the human chart's lyric event time, after the chart's own delay.
   - Report per song and pooled: the median absolute error; the share within 50, 100 and 250 ms; phrases whose
     first word is more than 500 ms off; and the run time on this CPU.
   - Also run each aligner on the full mix, to see what the separation buys.
4. **Choose** by pooled accuracy first, then robustness (no crash or garbage on long silences, repeated choruses,
   or words the aligner's vocabulary lacks), then install size and licence. Write the numbers and the choice into
   your report. If no candidate gets at least 70% of words within 250 ms, stop and report instead of building.

## Phase B: build

1. **`songcharter/engines/lyrics.py`:** align the given text to the vocal stem, and return word and syllable times
   in seconds of the decode.
   - Handle line breaks as phrase boundaries, and blank lines as section gaps.
   - Handle hyphenated syllables, apostrophes, punctuation, and words the model can't spell. Characters it cannot
     handle are kept in the display text, but aligned through a normalized form.
   - Cache the result like the other engines do, keyed by the stem, the text's hash and the settings.
   - Missing aligner libraries fall back cleanly: no lyrics, with a warning. They never fail a chart.
2. **The chart:** quantize each syllable start onto our grid as the notes are, and write `phrase_start`, `lyric`
   and `phrase_end` in [Events], with phrases split at line breaks and at rests longer than a threshold you set from
   the reference charts' phrase gaps (timings only).
   - scan-chart must still find the chart playable with 0 issues.
   - Clone Hero must read the lyrics: check with scan-chart's parse and its documentation.
3. **The CLI and the pipeline:** `songcharter chart SONG --lyrics FILE`, and `Options.lyrics` (a text, or None).
   pipeline.json records whether lyrics were added, how many words, and the alignment's own confidence measures.
   No word text goes anywhere but the chart (and the state folder until the song is charted: the app's rule).
4. **Dependencies:** a new optional extra, `lyrics`, and the lanes kept consistent: update both locks if needed,
   and `packaging/check_wheels.py` must still pass. M4-03 (install), building at the same time, may relock too.
   Keep your lock change minimal, and say exactly what changed so the orchestrator can merge it.
5. **Tests**, with made-up words and generated audio only:
   - the event format;
   - phrase splitting;
   - the cache;
   - the fallback when the aligner is missing;
   - no text left out or duplicated;
   - pipeline.json holds no words: assert this.
   Then check the tests by breaking the code.
6. **Golden charts:** with no `--lyrics`, no chart may move. Run the golden diff against main with `--expect none`.
   Optionally, report the reference songs charted WITH their lyrics, timing only, as the end-to-end accuracy.
7. **Docs:** a short DESIGN.md section, in its own style, giving the measured accuracy and the choice; `--lyrics` in
   the README; PROGRESS. Also add a note to `docs/work-orders/M4-06-ui-results.md` that the UI gets an optional
   "Paste lyrics" box, wired to `Options.lyrics`, at its build.

## Limits

- Keep new disk use under about 2.5 GB, model downloads included. The shared uv cache is not to be cleared.
- No model names or model identifiers in code, docs or commits. Name an aligner by its method or its package, not
  by an AI model's product name.

each check with its last lines, the golden verdict, and anything not done or uncertain.
