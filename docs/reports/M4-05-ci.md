## Choices the order did not spell out (each with its reason)

1. **`docker run --init`.** Not in the order's `docker run` line. Without an init, PID 1 is `sleep infinity`, which
   never reaps, so the node processes the cancel kills (their parent goes first) stay as zombies. `--init` reaps them
   as WSL's init does. `ui_guards.py` also counts a zombie as gone (it has exited) and lists it.
2. **The page charts a clip of its own** (`Söng for the page.wav`, 32 s). The clip phase's 30-s clip is warm by then
   (its guitar take cached), so it sends no `take` event (M4-04's merge note: "start cold or accept its absence").
   Starting cold keeps the check that matters.
3. **The cancel waits for node.** `take` is sent just before autochart's `node` starts (`autochart.generate` calls
   `on_take` and then runs the driver). So after the event `ui_guards.py` waits until `ac_headless.cjs` shows in the
   job's tree (required, 30 s), and then up to 30 s for `autochart-engine.cjs` (not required), before it posts the
   cancel. Otherwise a fast cancel could pass without proving that Node goes (the advisor's finding 4). In CI and on
   the dev machine both node processes were running at the cancel.
4. **Processes from /proc, not `ps`.** The Ubuntu docker images have no procps. `ui_guards.py` reads
   `/proc/<pid>/{stat,cmdline}` and prints the same `pid args` lines. It fails on any process whose program is node, or
   that runs ac_headless.cjs, autochart-engine.cjs, allin1_runner.py or `songcharter.cli chart`. It also fails on any
   process still in the job's tree as recorded at the cancel (the pids, sessions and process groups under the server).
   `--shared-machine` keeps only the tree check, for a dev machine where other agents run node.
5. **`--clip`** (required), plus `--server-log`, `--report` (JSON of the checks, both jobs' events and the tree at the
   cancel) and `--timeout`. The port comes from `--cmd`'s `--port`.
6. **Offline charts two clips.** The clip into a new folder (`Clip offline`), as the order says, but every stage up to
   the guitar is cached (decode to guitar), so only assemble and the preview run offline. Then a clip never charted
   (`new clip.wav`, 34 s) into `New clip offline`, so every stage runs with the network cut: the models (separation,
   ADTOF, allin1, autochart) come from the install alone. Both pass `check_gate.py`. Before charting, the phase proves
   the network is cut: curl to pypi.org must fail.
7. **The older Ubuntus run the whole `install` phase** (interrupted and rerun), then a phase `doctor-quick` (exit 0
   required).
8. **SIGTERM must also give exit status 0**, not only stop within 5 s. The server returns 0 after a clean stop.
9. **uninstall-all** also prints whether `~/.cache/uv` went (it did); it checks only the order's three paths.
10. **Reinstall "no download"** checks three things: no `fetch` line, no uv `Downloading`/`Downloaded` line, and no
    `downloading` line from install.sh itself.
