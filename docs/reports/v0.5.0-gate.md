### Findings

**1. A plain re-chart replaces version 1 in place, and its rating stays on it (minor; misleads, recoverable).**
- **Where:** `output_folder` gives a seed-0 chart the same folder whatever its options (`jobs.py:287-297`); feedback is read by chart id alone (`feedback.py:81-88`).
- **Reproduced:** rate version 1 as 5, then POST the same upload with `takes: 4`. The folder is rebuilt, and version 1 still shows 5.
- **Why it matters:** the friend trying Best on a song he already charted with Quick overwrites the Quick chart, against the brief's "nothing is overwritten". His rating then describes a chart he has not played.
- **Not lost:** the zip carries both `notes_sha` values, so the owner's side can tell.
- **Smallest fix:** when a record's `notes_sha` differs from the folder's notes.chart, the page says "you rated an earlier chart of this song". Whoever reads feedback.json should compare the two.

**2. An ordinary double-click on "Chart it differently" queues two versions (minor).**
- **Where:** the busy flag holds only while the request is out (`app.js:2022-2051`).
- **Reproduced:** two presses 150 ms and 300 ms apart on a plain row gave versions 4 and 5, then 6 and 7. Back-to-back clicks, and the lyrics panel's buttons, gave one.
- **Why it matters:** each extra version is a guitar take on his GPU and a row nothing on the page removes.
- **Smallest fix:** in `_again` (`server.py:957`), refuse while a version of that song waits or charts; or keep the button disabled for two seconds after a 202.

**3. A marked spot cannot be looked at on the owner's side (minor today, limits what the feature is for).**
- **Where:** the zip refuses notes.chart (`diagnostics.py:23-25`); feedback.json sends only the `pipeline` record (`feedback.py:227-252`).
- **Why it matters:** the rule promises the same chart "on that machine" (CLAUDE.md:54-56). The owner's GPU is another machine, and M8-02 found only 8 of 23 takes identical across devices. [inference: his card may not reproduce the friend's chart]
- **Smallest fix:** for each spot, add the Expert guitar notes within about 10 seconds of it as numbers (tick, frets, flags). The `[Events]` lyrics stay out.

**4. The draft's CI claims are ahead of the evidence.**
- Run 42740523718 (c72012e) was still in progress when I read it: Windows green, the Linux suite running.
- Main at 1611346 (run 42737378501) was in progress, and main at 0379f08 was cancelled. So no main run after M8-14's merge has finished; the same tree is green as 638db63 on its branch (42729465498).
- Run 42689305584 is an earlier head of the review fixes (c5a8f25). The merged fixes are green on main at e792d8a, run 42714080733; cite that one.
- **Fix:** wait for both runs, then correct the three citations.

**5. The owner's check has steps that will not work as written (see question 3).**
- "The guide's update line" fetches a release that is not published; he needs `bash install.sh --from <the folder of built files>`, as v0.4.0's gate did.
- The second chart in step 2 overwrites the first's folder, so there are no "two notes.chart files" to compare unless he records a hash first.
- The diagnostics zip holds only the newest five work folders; his check makes more.

**6. The reproducibility rule has gaps the record does not cover (question 4).**
- The engine's own Demucs and timing cache is keyed by the audio's hash alone (`eval/tools/autochart/ac_headless.cjs:169-178`).
- report.json keeps only each take's transcriber device (`pipeline.py:1512`, `folder_record` at 362).
- `threads` is not recorded.
- **Smallest fix:** record the driver's `devices` and `cachedStages` per take and the thread count, or narrow the rule's wording to "from an empty cache".

**7. A rating that cannot be saved shows an internal error with a path (minor).**
- **Where:** `_feedback` catches only `InputError` (`server.py:913-916`), so a full disk gives "internal error: OSError … <the state folder's path>" in the box.
- It is not lost silently; he sees it failed.
- **Smallest fix:** catch `OSError` and answer in the upload's words (`DISK_FULL`).

**8. Scope of one claim.** The 20-song set ran at f5e6383 only. The review fixes then touched `assemble.py`, `sections.py` and `separate.py`. The golden and stress sets were rerun identical at e792d8a and 638db63, which is enough; say so in step 3.
